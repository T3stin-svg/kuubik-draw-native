This prerelease closes the most important unproven path in the first visual
preview: pressing the compact Kuubik ribbon's LINE button and creating a real
native line with two canvas clicks.

## Native LINE proof

The smoke workflow runs inside the real Qt application:

1. create a new native document;
2. send a `QMouseEvent` to the ribbon button bound to the existing `DrawLine`
   `QAction`;
3. verify the LINE action became active;
4. click the first canvas point and require zero committed entities;
5. move the pointer and capture the native preview;
6. click the second canvas point and require exactly one new
   `RS2::EntityLine`;
7. save the document to DXF;
8. read the DXF with `ezdxf`, independently of the application.

The independent read-back found one non-zero LINE:

- start: `(122.0, 115.25, 0.0)`
- end: `(256.5, 50.0, 0.0)`
- length: `149.49184760380749`

The public evidence contains both the CI offscreen render and a 1920×1080,
96-DPI local Windows render. The local render shows the Kuubik Dark workspace,
visible menu and ribbon text, active `2 Points` button, blue preview line,
white committed line, right-side Layer/Block palette, bottom command line, and
the absence of a 3D view cube.

## Portable isolation correction

The first otherwise-green run found Qt's offscreen platform plugin in the CI
machine's Qt installation. A clean local replay exposed that the ZIP itself did
not contain the plugin. That result was treated as a false-positive packaging
gate and was not released.

The final package now ships `platforms/qoffscreen.dll`. The smoke process sets
`QT_PLUGIN_PATH` and `QT_QPA_PLATFORM_PLUGIN_PATH` to the copied portable folder,
so it cannot borrow the plugin from the build machine. The corrected package
then passed both GitHub CI and a second local run from a path containing spaces.

## Honest boundaries

This is a preview, not a production release and not a claim of full AutoCAD
parity. Guaranteed file workflows remain DXF open/save and vector PDF export.
DWG roundtrip, DWT and XREF parity are not certified. The ribbon still uses
GPL LibreCAD icons, and Properties opens the real LibreCAD dialog rather than a
permanent AutoCAD-style palette. No merge to `main` and no production deploy
were performed for this release.

The evidence is entirely synthetic. It contains no client drawing, private
AutoCAD reference image, environment file, credential, user profile path, or
application settings.
